# 实盘部署协议 v1：手动执行，top-15，价值/质量月度策略

## 1. 状态与授权

状态：`design_frozen_before_live_trial`

本协议把已验证的 v8 top-15 策略落地为个人手动执行的实盘流程。回答：

```text
如何在 500K 总资金下，用 20% 仓位运行周期性价值策略，
使得最坏年份（已知 -81% 策略回撤）对总资金的影响 <= -16%？
```

## 2. 策略概要（来自 v8 回测）

| 项 | 值 |
|---|---|
| 策略 | 四因子（ep/bm/div_yield/accruals）≥3 因子门槛 -> 中性化 -> ST/容量过滤 -> top-15 |
| 调仓频率 | 月度（月末信号，次月首个交易日 T+1 开盘执行） |
| 封存期回测 | +10.16%/yr，IR 0.92，MDD -16.6%（压力费后，相对 SH000852） |
| 2026 观察 | -81.1%/yr（价值逆风，观察区不构成验证） |
| 性质 | **周期性价值策略，非稳定 alpha**。价值顺风年强（2023 +25%），逆风年弱（2020 -9%、2026 -81%） |

**风险声明**：此策略在成长牛年会大幅跑输基准。20% 仓位设计的目的是将最坏情况
（策略 -81%）限制在总资金 -16%。这是已知风险，不是意外。

## 3. 资金与仓位

| 项 | 值 |
|---|---|
| 总资金 | 500,000 元 |
| 策略分配 | **100,000 元（20%）** |
| 保留资金 | 400,000 元（80%，不参与此策略） |
| 持仓数量 | 15 只，等权 |
| 单股目标仓位 | ~6,667 元（100,000 / 15） |
| 现金缓冲 | 每次调仓保留 ~2% 现金（~2,000 元）应对找零、手续费 |

**为什么不全仓**：v8 回测显示 2026 年策略回撤 -81%。20% 仓位下 = 总资金 -16%，
在个人可承受范围。100% 仓位下 = -81%，不可承受。

## 4. 每月操作流程

### 4a. 信号生成（月末最后交易日收盘后）

```bash
# 17:35 CST - 更新市场数据
cd /home/xiaocong/worksapces/qlib
/home/xiaocong/anaconda3/envs/qlib/bin/python \
    scripts/data_collector/update_daily_market_data_v1.py

# 17:45 CST - 生成下月持仓信号（需财务数据已更新到最新季报）
/home/xiaocong/anaconda3/envs/qlib/bin/python \
    scripts/run_daily_signal_pipeline_v1.py \
    --date <月末交易日> --top-k 15 --live
```

脚本输出（示例）：
```
BUY  (7):  000823.SZ, 002249.SZ, ...
SELL (7): 002027.SZ, 002745.SZ, ...
HOLD (8): 000683.SZ, 000700.SZ, ...
```

CSV 保存至 `output/live_ledger/signal_<date>.csv`。

### 4b. 执行（次月首个交易日开盘）

1. **卖出 SELL 列表**：开盘价或开盘后 5 分钟内，挂限价单（开盘价 ±0.5%）
2. **买入 BUY 列表**：卖出资金到账后，挂限价单（开盘价 ±0.5%）
3. **HOLD 不操作**

### 4c. 执行规则

| 情况 | 处理 |
|---|---|
| 涨停买不进 | 跳过，现金保留，不追单 |
| 跌停卖不出 | 次日再卖 |
| 部分成交 | 不追单，按实际成交持仓 |
| 停牌 | 不操作，沿用现有持仓 |
| 数据更新失败 | **沿用上月持仓，不调仓**，排查数据问题 |

**最小买入单位**：A 股 100 股/手。6,667 元可买：
- 100 元/股以下的股票：约 1 手（100 股）
- 50 元/股以下的股票：约 1-2 手
- 高价股（>100 元/股）：可能买不满 1 手 -> 跳过该股，仓位空缺

**处理方式**：如果某只因高价无法买入 1 手，跳过该股，其份额分配给现金缓冲。
不调整其他股票的权重（保持等权，实际持仓可能 <15 只）。

## 5. 风控规则（叠加在信号之上）

### 5a. 硬止损（最高优先级）

| 条件 | 动作 |
|---|---|
| 策略仓位（100K）从建仓以来最高点回撤 > 30% | **全部清仓，暂停 1 个月** |

计算：策略仓位净值 = sum(持仓市值) / 100,000。记录每次调仓时的净值。
如果当前净值 / 历史最高净值 - 1 < -30%，全部卖出，下月不调仓，再下月恢复。

**目的**：防止价值逆风期深度回撤（如 2026 年 -81%）。30% 止损 = 最大损失
100K × 30% = 30K = 总资金 6%。

### 5b. 风格风控（不叠加）

v7（单 BM HML）和 v9（同轴 HML）均失败。**风格择时路线已关闭**。
不叠加任何风格风控信号。周期性风险由仓位管理（20%）和硬止损（5a）兜底。

### 5c. 数据中断

如果某月数据更新失败（Tushare API 故障、财务数据未更新等）：
- 沿用上月持仓，不调仓
- 记录中断原因
- 数据恢复后下月正常调仓

## 6. 记录与复盘

### 6a. 每月记录

每次调仓后记录到 `output/live_ledger/`：

| 文件 | 内容 |
|---|---|
| `signal_<date>.csv` | 信号列表（BUY/SELL/HOLD + 权重），脚本自动生成 |
| `execution_<date>.csv` | 实际成交记录（手动填写：ts_code, action, fill_price, shares, fill_time） |
| `nav_log.csv` | 每月策略净值（手动填写：date, nav, cash, holdings_value） |

### 6b. 月度复盘检查项

1. 策略仓位净值是否触发硬止损（5a）
2. 实际持仓与信号列表的差异（涨跌停、停牌导致）
3. 执行滑点 vs 回测假设（开盘价 ±0.5% vs 实际成交价）
4. 数据更新是否正常

### 6c. 季度复盘检查项

1. 策略实际表现 vs SH000852 基准
2. 累计超额收益走势
3. 是否出现回测未预期的行为

## 7. 已知限制（如实标注）

1. **财务数据滞后**：策略依赖季报 PIT 数据。季报披露有 1-4 个月滞后，
   最新季报未披露时用上一季。信号生成脚本会自动处理（`available_date` 过滤）。
2. **容量假设**：回测用 100M 账户验证容量。实盘 100K 远小于回测，容量无约束，
   但最小买入单位（100 股）在高价股上可能受限。
3. **周期性风险**：策略在成长牛年（如 2020、2026H1）会大幅跑输。这不是 bug，
   是策略特性。20% 仓位 + 30% 硬止损是风控兜底。
4. **手动执行偏差**：开盘价 vs 实际成交价存在偏差。回测假设 T+1 开盘执行，
   实盘可能在开盘后几分钟才成交。
5. **单因子依赖**：策略 alpha 集中在价值/质量复合因子。如果该因子持续失效
   （如 2021 后 Alpha158 衰减），策略可能需要重新评估。

## 8. 不做的事

- 不做自动下单（手动执行）
- 不叠加风格风控信号（v7/v9 均失败，路线关闭）
- 不在实盘中调优参数（top-k、因子权重、调仓频率等）
- 不用杠杆
- 不把保留资金（80%）投入其他策略（除非有新的已验证策略）

## 9. 退出条件

以下任一条件触发时，停止策略并复盘：

1. 硬止损触发（策略仓位回撤 > 30%）
2. 连续 6 个月跑输基准（SH000852）
3. 策略逻辑被证伪（新研究发现价值/质量因子在 A 股持续失效）
4. 数据管道无法维护（Tushare 停服、qlib 不兼容等）
