# 更正：账户规模结论（50 万 vs 1 亿）—— 小资金反而是优势

| 项 | 值 |
|---|---|
| 触发 | 上一轮发现流动性过滤修复使 1 亿口径大幅下修 |
| **更正** | 原结论"50 万与 1 亿无实质差异（≤0.25pp）"**是 no-op 缺陷造成的假象**；修复后 **50 万口径反而高约 +4.9pp** |
| 日期 | 2026-09-13 |

## 1. 原结论为何错了

修复前，`load_amount_avg` 返回零列 → 流动性过滤在**两个口径下都不生效**
→ 两者使用**完全相同的池** → 结果自然几乎相同（+13.83% vs +14.08%，差 0.25pp）。
我当时据此得出"账户规模不影响策略"。**但那是因为两者被同一个 bug 抹平了。**

## 2. 修复后的真实情况

| 配置 | 流动性门槛 | 通过比例 | full 净超额（10日+否决，stress） |
|---|---|---|---|
| **50 万**（top30） | 66.7 万元/日 | **98.9%** | **+13.45%**（IR 1.172） |
| 1 亿（top15 口径阈值） | 1.33 亿元/日 | **34.7%** | **+8.57%**（IR 0.763） |

**差异 +4.88pp，方向是"小资金更好"。**

## 3. 机制：不是"资金规模"直接起作用，而是它通过流动性门槛起作用

```text
资金小  ->  单笔小  ->  所需流动性门槛低  ->  池几乎不受限 (98.9%)
                                            ->  保留中小市值/低价段  <- 收益来源在这里
资金大  ->  单笔大  ->  门槛高            ->  池被压缩到最活跃的约 1,000 只
                                            ->  被迫放弃中小市值/低价段
```

这与本项目此前的独立发现完全一致：
- `lowprice`（低名义价格）是六个底仓中**唯一**为正的单因子（+4.82%）；
- 低价/中小市值段是收益来源，而**大资金进不去**。

**→ 结论：对本策略而言，50 万不是限制，而是优势。**
机构若用 1 亿做同一策略，只能拿到约一半的超额（+8.57% vs +13.45%）。

## 4. 这也解释了 1 亿口径为何下修那么多

1 亿口径下过滤剔除的是**收益最高的那部分标的**（流动性差的中小盘），
所以过滤一生效，headline 就从 +14.08% 掉到 +8.57%。
**过滤在 50 万口径下无害、在 1 亿口径下有害**，是"门槛绑定程度"的必然结果。

## 5. 仍成立的结论

| 结论 | 状态 |
|---|---|
| 策略在 50 万口径下的全部数字 | **成立**（+16.01% / IR 1.349） |
| 毒尾否决有效 | **成立**，但 1 亿口径下增量由 +5.19 → **+4.04pp** |
| 前瞻性检验（滞后1日） | **成立**，1 亿口径下由 +4.68 → **+3.44pp** |
| 定义稳健性 12/12 | **待复核**（在修复前的 1 亿基座上跑的，本轮已重跑） |
| 底仓迁移 4/6 | **成立**（在 50 万快照上跑的，50 万口径受修复影响可忽略） |
| 账户规模无差异 | **✗ 更正为：50 万更优 +4.88pp** |

## 6. 教训（补充到治理规则）

**用"两个配置结果相同"来论证"该因素不重要"时，必须先证明两个配置真的不同。**
本案例中两者相同，唯一原因是共同的上游 bug 把它们都抹平了。
**"无差异"本身可能是缺陷的症状，而不是结论。**
