# 自动化监测：承重墙报警 + 静默失效哨兵

| 项 | 值 |
|---|---|
| 脚本 | `scripts/migration/wsl_run_monitor_all.sh`（编排）、`scripts/analyze_strategy_return_attribution_v1.py`（报警逻辑） |
| 用途 | 实盘期间定期自检：策略是否仍处有效形态 + 关键量是否异常 |
| 首次运行 | 2026-09-13 通过（exit 0，无报警） |
| 日期 | 2026-09-13 |

## 1. 为什么需要它

收益归因显示（见 `a_share_return_attribution_v1.md`）：**2016-2019 之后，
策略超额主要来自毒尾否决而非选股 alpha；基础价值因子近年为负（最近 −22.0%）。**
即 **否决是承重墙，否决失效 = 策略失效**。

但"承重墙"此前只写在文档里——**实盘时没人会每天翻文档**。本轮把它做成报警。

## 2. 三段式监测

```bash
wsl.exe bash /mnt/d/workspaces/qlib/scripts/migration/wsl_run_monitor_all.sh
```

| 段 | 内容 | 触发 |
|---|---|---|
| [1/3] 衰减监测 | 滚动 12 个月净超额（vs 中证1000） | 单口径转负**只记录**（因两个基准可能背离） |
| [2/3] **承重墙报警** | 滚动 12 个月：基础 alpha / **否决** / 价格过滤 / 合计 | **否决贡献 < 0 → 报警，退出码 2** |
| [3/3] 静默失效哨兵 | 三个量级断言 | 任一 FAIL → 先怀疑实现缺陷，而非策略变化 |

**新增的一个有用统计**：**历史否决贡献为正的滚动窗口比例 = 66.0%**。
即否决在约 **2/3** 的滚动 12 个月窗口里贡献正超额——
**它是"多数时候有效"，不是"几乎总是有效"**。实盘预期应据此设定。

## 4. 使用建议

| 频率 | 动作 |
|---|---|
| 每 10 个交易日 | 更新数据 → 重跑 `wsl_run_holdings.sh` 生成新信号 |
| 每月 | 跑 `wsl_run_monitor_all.sh`；**退出码 2 即需复核** |
| 报警触发时 | 检查是否为实现缺陷（先看 [3/3] 断言）→ 再看数据是否更新 → 最后才判定策略失效 |

**重要**：[3/3] 的断言顺序是刻意的——
**历史上本项目的所有重大错误都是"静默失效"（不报错但结果错）**，
所以发现异常时的第一反应应该是查实现，而不是接受"策略变差了"这个结论。

## 5. 结论边界

1. 监测基于**回测/模拟净值**，实盘需接入真实成交后重算。
2. 66% 的胜率意味着**约 1/3 的滚动窗口里否决会拖累或无效**——
   这不构成"策略失效"，但意味着实盘需要承受这类时段。
3. 报警阈值（否决贡献 < 0）是**冻结的**，不做调参。
